# SalRenTax

A production-quality, multilingual, multi-country salary/tax/rent/labor
calculator platform. Phase 1A: architecture proof with one fully working
US paycheck calculator.

## Overview

SalRenTax is locale-first, not translation-first: every country/language
pair (`en-US`, `en-GB`, `pt-BR`, ...) gets its own currency, tax rules,
terminology, and page availability. Nothing is auto-translated, and no
locale is shown as "ready" until it actually has verified data and
localized content behind it.

Only `en-US` is active right now. The other seven locales in the roadmap
(`en-GB`, `en-IE`, `pt-BR`, `es-ES`, `es-MX`, `de-DE`, `nl-NL`) are typed
and tracked in the [page registry](src/seo/page-registry.ts) and
[locale status map](src/i18n/types.ts) with status `coming-soon` — they
are never built, linked, or sitemapped.

## Tech stack

| Layer           | Technology                                                  |
| --------------- | ----------------------------------------------------------- |
| Framework       | Astro 7 (static output)                                     |
| Language        | TypeScript (strict mode)                                    |
| Islands         | Preact                                                      |
| Styling         | Tailwind CSS v4                                             |
| Testing         | Vitest                                                      |
| Linting         | ESLint (flat config) + Prettier                             |

## Requirements

- Node.js >= 22.12
- pnpm (`npm install -g pnpm` if you don't have it)

## Installation

```bash
pnpm install
```

## Commands

```bash
pnpm dev       # start the dev server
pnpm test      # run the Vitest suite
pnpm check     # astro check (TypeScript + Astro template diagnostics)
pnpm lint      # ESLint
pnpm format    # Prettier --check
pnpm build     # production build to dist/
pnpm preview   # preview the production build locally
```

## Environment variables

| Variable          | Purpose                                                                  | Default if unset                                                               |
| ----------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `PUBLIC_SITE_URL` | Base URL used for the sitemap, canonical links, Open Graph, and JSON-LD. | `https://example.com` (a deliberate placeholder — never a guessed real domain) |

Copy `.env.example` to `.env` and set the real production domain before a
production build/deploy:

```bash
cp .env.example .env
# then edit .env: PUBLIC_SITE_URL=https://salrentax.com
```

## Current active routes

```
/
/en-us/
/en-us/salary/
/en-us/salary/paycheck-calculator/
/404
```

These are generated by explicit page files under `src/pages/`, driven by
the `status: 'active'` entries in `src/seo/page-registry.ts`. The registry
is the single source of truth for what's live — nothing is hard-coded as
a page count anywhere in the app.

## Currently supported locale

**en-US only.** US federal income tax (2026) and FICA figures are sourced
from official IRS and SSA publications — see [DATA-SOURCES.md](DATA-SOURCES.md)
for citations, coverage, and what is _not_ yet implemented (state/local
tax, head-of-household filing status, Additional Medicare Tax).

## Project structure

```
src/
├── i18n/            # locale types, utils, en-US translation dictionary
├── data/
│   ├── locales/      # LocaleConfig per locale (only en-US populated)
│   └── salary/us/    # sourced US tax data
├── calculators/
│   ├── core/          # pure math utilities (progressive tax brackets)
│   └── salary/engines/ # country-specific calculation engines (usPaycheck)
├── seo/               # page-registry.ts (source of truth for generated pages)
├── lib/seo/           # metadata, hreflang, structuredData (JSON-LD), site URL
├── components/         # navigation, calculator UI, ads, seo, islands (Preact)
├── layouts/            # BaseLayout.astro
└── pages/              # file-based routes, one per active registry entry
tests/                  # Vitest specs mirroring the src/ structure
```

## Known limitations (Phase 1A)

- Only `en-US` has real data, content, and pages. All 7 other roadmap
  locales are typed but intentionally unbuilt.
- Only one calculator exists: the US paycheck calculator. Hourly wage,
  gross-to-net, tax, rent, and labor calculators are not implemented yet.
- No state/local income tax. No head-of-household filing status (its
  federal bracket schedule hasn't been verified yet). No Additional
  Medicare Tax for high earners.
- No catch-all route — pages are explicit `.astro` files under
  `src/pages/`. A data-driven `[...slug].astro` catch-all is a
  reasonable Phase 1B improvement once there are enough pages to justify it.
- Ads are placeholder slots only — no real ad provider is wired in.
- No CI pipeline configured yet (this repo's `test`/`check`/`lint`/`build`
  scripts are meant to be run in CI once one is added).

## Roadmap (next phases)

See the original project brief's phase plan: 1B (shared calculator
engines: hourly wage, salary-to-hourly, rent affordability, etc.), 2
(country data for the remaining 7 locales, each gated on source
verification), 3 (locale expansion — only once content/translations/data
exist), 4 (state/region pages), 5 (SEO/content polish), 6 (full audit).

Decisions behind the current architecture are recorded in
[DECISIONS.md](DECISIONS.md). Current verification status and command
output are in [PHASE-1A-STATUS.md](PHASE-1A-STATUS.md).
